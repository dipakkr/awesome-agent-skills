# Component Study

Create an elegant exploded product concept poster from your approved component list, preserving part count and making the relationship between pieces readable.

## Composition decisions

1. Require the component list and known materials. With no actual SKU reference, use explicit fictional concept mode in the brief and delivery; do not invent hidden mechanisms of a real product.
2. Count components before composing. Use an axial stack for nested parts, a fan for flat pieces or an orbit around a shell only when the relationship remains intelligible.
3. Keep matched scale, viewpoint and lighting across parts. Separate silhouettes and avoid duplicate components. Arrows and callouts must not imply repair order or engineering tolerances.
4. Use exact short title if requested. Omit all unsupported measurements, specifications, certification marks and invented brand marks. This is a concept communication visual, not an assembly manual.

## Runtime inputs

Accept the subject/source, audience, placement, aspect ratio, exact short copy, optional palette, authorised reference images and optional logo directly in the request. No manual skill edits. Default to one output; if a set is requested, plan distinct concepts. Example subjects in this package are demonstration briefs, never mandatory defaults.

Without a logo, omit it and rebalance the composition. Never add a placeholder, publisher logo or replacement instruction to the artwork. A supplied exact logo/product reference needs an image-edit or compositing path that preserves identity; inspect it before and after. If fidelity fails, disclose it and offer a clean alternative rather than inventing a mark or claim.

## Generate and validate

Use an available image-generation tool for the actual raster artwork. Do not claim an image was created if only a prompt was written. The user's agent/tool account determines image costs; no particular paid provider is required. Native Claude Code image generation is not implied.

Freeze the brief and exact copy first. For the renderer, list the approved component names/materials and exact visible strings explicitly; do not pass unresolved workflow instructions as if they were product facts. Reject any added material or specification annotation, even when plausible. Save every generation attempt, full prompt, actual tool, input/output hashes and measured dimensions. Use one independent image per variation; crops, alternate downloads and recolours alone are not distinct concept examples. Inspect the complete image and at intended reading size: wording, counts, relationships, reference fidelity, margins and the style decisions above. Correct specific defects with the image tool and retain rejected attempts.

Deliver accepted image files, alt text, a short use note and editable brief/prompt. These are editable generation inputs, not layered PSDs or vector artwork. Report actual dimensions and tested limits. Do not promise commercial performance, platform approval or exact product reconstruction from a concept.
