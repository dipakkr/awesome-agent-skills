# Paper Depth Covers

Build a tactile editorial cover from cut-paper shapes, controlled depth and one clear metaphor, using your own subject and optional headline.

## Composition decisions

1. Choose one metaphor that explains the brief without depicting a factual event. Reduce it to a foreground subject, two supporting planes and a quiet background.
2. Use visible fibrous paper edges, a consistent oblique light direction and believable layer shadows. Avoid plastic bevels, fake interface labels and a miniature photograph aesthetic.
3. Give silhouette and negative space more weight than decoration. Keep the subject within a central safe zone; leave headline space only when requested, never print placeholder words.
4. Vary scene topology across a set: a nested aperture, a flowing diagonal, a bridge across a gap or a central branching structure. Keep paper material and lighting coherent.

## Runtime inputs

Accept the subject/source, audience, placement, aspect ratio, exact short copy, optional palette, authorised reference images and optional logo directly in the request. No manual skill edits. Default to one output; if a set is requested, plan distinct concepts. Example subjects in this package are demonstration briefs, never mandatory defaults.

Without a logo, omit it and rebalance the composition. Never add a placeholder, publisher logo or replacement instruction to the artwork. A supplied exact logo/product reference needs an image-edit or compositing path that preserves identity; inspect it before and after. If fidelity fails, disclose it and offer a clean alternative rather than inventing a mark or claim.

## Generate and validate

Use an available image-generation tool for the actual raster artwork. Do not claim an image was created if only a prompt was written. The user's agent/tool account determines image costs; no particular paid provider is required. Native Claude Code image generation is not implied.

Freeze the brief and exact copy first. Save every generation attempt, full prompt, actual tool, input/output hashes and measured dimensions. Use one independent image per variation; crops, alternate downloads and recolours alone are not distinct concept examples. Inspect the complete image and at intended reading size: wording, counts, relationships, reference fidelity, margins and the style decisions above. Correct specific defects with the image tool and retain rejected attempts.

Deliver accepted image files, alt text, a short use note and editable brief/prompt. These are editable generation inputs, not layered PSDs or vector artwork. Report actual dimensions and tested limits. Do not promise commercial performance, platform approval or exact product reconstruction from a concept.
